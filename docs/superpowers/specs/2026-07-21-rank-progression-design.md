# Rank Progression Design — XP, Levels, Ranks, Cosmetics

Date: 2026-07-21 · Status: approved by Brian (interactive session)

## Summary

Mana gains a lifetime progression system. Total tokens ever used across Claude
Code and Codex become XP on an exponential (Pokémon-style) leveling curve.
Levels unlock ranks; ranking up is a deliberate act via a **Rank Up** button
that opens a lavish tier-themed dialog. Rank drives cosmetics: the widget
border and the mage sprites both start **naked** and gain increasingly
majestic dress per tier. Sprite art is generated by Codex CLI from briefs in
`docs/art/` — never hand-drawn in this repo. Border themes are hand-crafted
CSS.

## XP source (approved: all tokens count)

- Claude: sum every `message.usage` field — `input_tokens`,
  `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens` —
  from `~/.claude/projects/**/*.jsonl`.
- Codex: `token_count` events carry cumulative `total_token_usage` per
  session file in `~/.codex/sessions/**/*.jsonl`; count a session's latest
  `total_tokens` value (it is a running total — do not sum every event).
- Incremental scanning: persist per-file byte offsets (Claude) / last seen
  totals (Codex) so re-scans never double-count. New files are picked up on a
  poll interval (60s); a full startup scan reconciles history the first time.

## Leveling curve (approved: cubic fast curve)

- `xp = floor(total_tokens / 1000)`
- Total XP required to *reach* level L: `xpForLevel(L) = floor(0.8 · L³)`,
  level 1 at 0 XP.
- `levelForXp(xp)` = the largest L with `xpForLevel(L) ≤ xp`.
- Constants (`TOKENS_PER_XP`, curve coefficient) live in one tested module so
  pacing is a one-line tweak.

## Ranks (approved: widening gates)

Rank 0 is **naked** (the starting state: no border, unarmored sprites).
Tiers, with the level required to *become eligible* for each:

| # | Tier | Gate level | # | Tier | Gate level |
|---|------|-----------|---|------|-----------|
| 1 | plastic | 5 | 8 | emerald | 55 |
| 2 | wood | 10 | 9 | diamond | 66 |
| 3 | iron | 15 | 10 | master (red) | 78 |
| 4 | bronze | 21 | 11 | legend (purple) | 91 |
| 5 | silver | 28 | 12 | champion (radiant gold/blue) | 105 |
| 6 | gold | 36 | 13 | godlike (heavenly) | 120 |
| 7 | platinum | 45 | | | |

- Rank NEVER auto-advances. When `level ≥ gate(rank + 1)`, a glowing
  **Rank Up** button appears in the widget's top-right. Clicking opens the
  rank-up dialog; confirming advances exactly one tier and persists.
- Multiple gates crossed → rank up repeatedly, one lavish dialog per tier.

## Architecture

Rust owns all progression state and math (single source of truth); the
frontend only renders.

- New `src-tauri/src/progress.rs`:
  - Tally scanner (dirs injectable for tests), curve + gate math, state
    persistence at `app_data_dir()/progress.json`
    (`{ total_tokens, rank, claude_offsets, codex_totals }`).
  - Emits `progress-update` `{ xp, level, rank, eligible }` on change;
    commands `get_progress()` and `rank_up()` (validates eligibility
    server-side, returns the new progress).
- Frontend (`src/main.ts` + new `src/progress-view.ts` pure helpers):
  - Footer strip under the provider cards: `Lv 12 · Silver` + a thin XP bar
    toward the next level (reuses meter styling language).
  - Top-right **Rank Up** button, only rendered when eligible; must opt out
    of the drag region. Non-activating panel: mouse-only interaction
    (`acceptFirstMouse` already set), no keyboard paths.
  - Rank-up dialog: full-widget overlay, tier-themed (gradient, ornament,
    title like "ASCEND TO GOLD"), Confirm/Later. Confirm → `rank_up()` →
    cosmetics apply.

## Cosmetics

- `#root` gets `data-rank="<tier>"`; `src/styles.css` defines 14 border
  themes (naked through godlike) — border gradients, glows, corner ornaments —
  respecting the concentric-corner formula (inner = outer − inset). Naked =
  no border, no corner ticks.
- Sprites: per-tier sheets `public/sprites/<provider>-rank-<tier>.png`, same
  geometry as today (224×168 PNG; 4 frames × 3 state rows of 56×56;
  states idle/working/hover top-to-bottom; transparent background). The
  *naked* base sheets are also new art (unarmored mages). Missing sheet →
  fall back to the current art so the app never breaks while art lands.
- Art generation: briefs + per-tier prompts in `docs/art/`; Codex CLI
  (`codex exec`) is invoked to generate the sheets. If Codex cannot produce
  images in this environment, the briefs remain the handoff artifact.

## Testing

- Rust: curve math, gate eligibility, incremental tally (fixture JSONL files,
  offset/duplicate-count cases), rank_up validation.
- Vitest: progress-view pure helpers (footer text, xp-bar fraction, button
  visibility, dialog copy), styles assertions for rank themes.

## Out of scope

- No XP from other tools/providers; no de-leveling; no server sync; no
  prestige system; no settings UI for pacing constants.
